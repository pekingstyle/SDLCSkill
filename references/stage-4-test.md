# Stage 4 — Test：交给人之前先自证；配置本身要过回归

传统的"能用"信号到得太晚（CI 几分钟 / 测试员几天 / 生产几周）——agent 产码时，晚信号意味着人得全量检查，人成瓶颈。所以：**会话在人来之前自检自修**；驾驶 agent 的配置（项目记忆/skills/hooks/模型/prompt）按"配置即代码"做回归。

## 反馈环（每次会话）
1. 必须有自证手段：测试、构建、或截图 diff。没有就先建，再干活。
2. 改 → 跑验证 → 读结果 → 再改，**通过才向人交付**；"跑不了所以没跑"不是合法的完成状态。
3. 修复任务 failing test first：先写复现测试、**看着它失败**，再修到绿（hook 拦截改测试文件，见 scripts/hook-protect-test-files.sh）。
4. 完成报告贴工具链证据（测试输出/构建日志/截图 diff），不是 agent 自评。
5. 需要更强保证时：verifier 以**全新上下文**做最终裁决（定义见 governance.md）——不被产生代码的那些假设污染。

## Evals（配置回归；架设与用例格式见 `../evals/README.md`）
- 触发：定时 + 凡项目记忆/skills/hooks/模型/prompt 变更必跑。
- 纪律：失败阻止合并（修好，或有理由地退役用例）；eval 失败归因指向配置就修配置，**不许改 eval 迁就行为**；每起事故 = 补 1 条 eval。

## 闸门（出）
验证证据齐备 → 开 PR 进 Stage 5。

## 本阶段禁令
无反馈环空口宣称完成；改测试让失败测试通过；改配置不过 eval。
